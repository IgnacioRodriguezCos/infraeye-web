HECHO NUEVO VERIFICADO EN EL CODIGO (commits 0af5cc5 y b24b750):
- Las metricas de memoria (mem_usedPercent) y disco (disk_usedPercent) en
  instancias Linux solo las expone el agente de Cloud Eye (CES Agent /
  UniAgent, namespace AGT.ECS). Sin el agente solo hay CPU, tasas de red y
  tasas de disco.
- La plataforma: detecta la ausencia (notas de "datos faltantes" por
  instancia), verifica si el agente esta instalado (metricas AGT.ECS) y
  puede instalarlo de forma automatizada via user data + reinicio, con
  autorizacion del usuario (endpoint install-ces-agent + botones en la web).
- Ademas: encendido/apagado de instancias desde la plataforma y exclusion
  del analisis de las instancias apagadas (SHUTOFF) con motivo informado.

REPOSICIONAMIENTO (que muere y que sobrevive):
- MUERE: "sin agentes" a secas, "capa de analisis externa que no despliega
  componentes", "las credenciales solo se usan para lecturas".
- SOBREVIVE: "sin agentes DE TERCEROS". InfraEye no instala software
  propietario externo (como Datadog/Dynatrace/New Relic); depende del agente
  NATIVO del proveedor (componente estandar de la telemetria de la
  plataforma), y su instalacion es automatizada y autorizada caso por caso.
- Las operaciones de escritura (instalar agente + reinicio, encender/apagar)
  son explicitas y autorizadas por el usuario; el analisis en si sigue
  siendo de solo lectura.

1. NUEVO CASO DE USO (despues de CU08, antes de Requerimientos Funcionales)
--------------------------------------------------------------------------------
  ----------------------------------------------------------------
  \subsubsection{CU09 -- Instalar agente de monitoreo en una instancia}

  \paragraph*{Objetivo}

  Habilitar la recolección de las métricas de memoria y de utilización de disco en instancias Linux que no exponen dichas métricas por ausencia del agente de monitoreo del proveedor.

  \paragraph*{Precondiciones}

  \begin{itemize}
  \item El usuario ha iniciado sesión.
  \item La cuenta de Huawei Cloud se encuentra vinculada (CU02).
  \item La instancia objetivo se encuentra encendida.
  \end{itemize}

  \paragraph*{Flujo principal}

  \begin{enumerate}
  \item El usuario selecciona la instancia que presenta métricas faltantes y la opción \textbf{Instalar agente de monitoreo}.
  \item El sistema consulta las métricas del espacio de nombres del agente (AGT.ECS) para verificar si el agente ya se encuentra instalado.
  \item El sistema solicita la confirmación del usuario, informando que la instalación requiere el reinicio de la instancia.
  \item El usuario confirma la operación.
  \item El sistema inyecta el script de instalación del agente en los datos de usuario de la instancia.
  \item El sistema reinicia la instancia para que el script se ejecute durante el arranque.
  \item El sistema verifica la instalación comprobando la presencia de las métricas del agente.
  \item El sistema informa al usuario que la instancia quedó habilitada para la recolección de memoria y disco.
  \end{enumerate}

  \paragraph*{Flujos alternativos}

  \subparagraph{A1 -- El agente ya se encuentra instalado}

  En el paso 2:

  \begin{itemize}
  \item El sistema detecta métricas del agente en la instancia.
  \item Informa al usuario que el agente ya se encuentra instalado y no se reinstala.
  \item Finaliza el caso de uso.
  \end{itemize}

  \subparagraph{A2 -- La instancia se encuentra apagada}

  En el paso 1:

  \begin{itemize}
  \item El sistema detecta que la instancia está apagada.
  \item Informa al usuario que la instalación requiere la instancia encendida.
  \item Si el usuario enciende la instancia, el caso de uso continúa en el paso 2; de lo contrario, finaliza.
  \end{itemize}

  \subparagraph{A3 -- Error durante la instalación}

  En los pasos 5 a 7:

  \begin{itemize}
  \item El sistema detecta un error al inyectar el script, reiniciar la instancia o verificar las métricas.
  \item Informa el problema al usuario.
  \item Finaliza el caso de uso sin dejar la instalación en estado inconsistente.
  \end{itemize}

  \paragraph*{Resultado}

  Al finalizar el caso de uso la instancia ejecuta el agente de monitoreo del proveedor y expone las métricas de memoria y de utilización de disco, que quedan disponibles para los análisis posteriores.

--------------------------------------------------------------------------------
  ----------------------------------------------------------------
  \subsubsection{RF15 -- Instalación del agente de monitoreo}

  \noindent \textbf{Descripción:}

  El sistema deberá detectar las instancias que no exponen métricas de memoria o de utilización de disco por ausencia del agente de monitoreo del proveedor, informar la limitación en los resultados del análisis y, con la autorización explícita del usuario, instalar el agente de forma automatizada, verificando su presencia antes de intentar la instalación y su funcionamiento después de completada.

  \noindent \textbf{Prioridad:}

  Media.

  \noindent \textbf{Casos de uso relacionados:}

  \noindent CU09 -- Instalar agente de monitoreo en una instancia.

Insertar DESPUES del parrafo de granularidad/paginacion:

  ----------------------------------------------------------------
  La disponibilidad de las métricas depende del tipo de instancia y de la
  presencia del agente de monitoreo de Huawei Cloud. Las métricas de CPU y
  de tráfico de red se exponen de forma nativa, mientras que las de
  utilización de memoria y de disco en instancias Linux solo las reporta el
  agente del proveedor (espacio de nombres AGT.ECS). El sistema consulta las
  métricas en los espacios de nombres del sistema y del agente; cuando el
  agente no se encuentra instalado, identifica las métricas faltantes por
  instancia, lo informa en los resultados del análisis y ofrece la
  instalación automatizada del agente con autorización del usuario (véase
  CU09). Las instancias que se encuentran apagadas se identifican por su
  estado y se excluyen del análisis, informando el motivo.
