PARTE 1 — NUEVA SUBSECCION EN TECNOLOGIAS
--------------------------------------------------------------------------------
  ----------------------------------------------------------------
  \subsection{Agente de Infraestructura como Código}

  La materialización de las recomendaciones como cambios reales de
  infraestructura se apoya en un servicio complementario: un agente de
  Infraestructura como Código para Huawei Cloud, desarrollado a partir del
  proyecto \emph{agent-huawei-cloud} de Agustín Chiarenza —uno de los
  especialistas entrevistados durante el relevamiento de este trabajo—, del
  cual se derivó el subconjunto de funcionalidades de chat IaC y de
  protecciones de ejecución (\emph{guardrails}).

  El agente está implementado en Python sobre el framework FastAPI —stack
  del proyecto del cual deriva—, utiliza SQLAlchemy como mapeador
  objeto-relacional y Alembic para las migraciones de su base de datos
  PostgreSQL, y ofrece su propia interfaz web de chat desarrollada en
  JavaScript. Su componente central es el ejecutor de Terraform, protegido
  por un conjunto de \emph{guardrails}: validación sintáctica del código HCL
  generado, exigencia de etiquetas de propiedad sobre los recursos,
  estimación del costo de cada operación y una cola de aprobaciones que
  requiere la confirmación explícita del usuario antes de ejecutar cualquier
  cambio (\emph{approve} $\rightarrow$ \emph{apply}).

  La comunicación entre la plataforma y el agente se realiza mediante su
  API: una cuenta de servicio registrada automáticamente, autenticación por
  tokens y envío cifrado de las credenciales del usuario, que el agente
  almacena cifradas en su propia base de datos. Cuando el usuario decide
  materializar una recomendación, la plataforma envía al agente el flavor
  recomendado; el agente escribe el código HCL del módulo \emph{huawei-ecs},
  ejecuta el ciclo \emph{init} $\rightarrow$ \emph{validate} $\rightarrow$
  \emph{plan} de Terraform de manera determinística —sin intervención de
  modelos de lenguaje en esta etapa— y deja la operación propuesta en la
  cola de aprobaciones, con el plan y el costo visibles. La aplicación del
  cambio se ejecuta únicamente tras la aprobación del usuario.

  Cabe señalar que la capacidad de chat del agente se apoya en un modelo de
  lenguaje accesible mediante los servicios de inteligencia artificial del
  proveedor, orientada a consultas de infraestructura como código; el flujo
  de aprovisionamiento descrito, en cambio, es enteramente determinista, de
  modo que las operaciones críticas no dependan de la salida de un modelo
  generativo.

PARTE 3 — OPCIONAL (decision pendiente): CU Y RF DEL APROVISIONAMIENTO
--------------------------------------------------------------------------------
El boton "Levantar instancia con Terraform" existe en la aplicacion. Si el
tutor ve la demo, conviene que el flujo este formalizado. Texto listo si
deciden sumarlo (serian CU10 y RF16):

  \subsubsection{CU10 -- Materializar una recomendación mediante el agente
  de Infraestructura como Código}

  Objetivo: aplicar una recomendación de optimización aprovisionando la
  instancia propuesta, con aprobación explícita del plan.

  Precondiciones: sesión iniciada; cuenta vinculada; análisis con
  recomendación de flavor disponible; agente IaC en ejecución.

  Flujo principal:
  1. El usuario selecciona la instancia con recomendación y la opción
     "Levantar instancia con Terraform".
  2. El sistema solicita los parámetros obligatorios (imagen y contraseña
     de administración) y opcionales (nombre, zona, propietario).
  3. El sistema envía al agente IaC el flavor recomendado junto con los
     parámetros.
  4. El agente genera el código HCL del módulo, ejecuta
     init->validate->plan y registra la operación en la cola de
     aprobaciones con el plan y el costo estimado.
  5. El usuario revisa el plan y el costo, y aprueba la operación.
  6. El agente ejecuta el apply y informa el resultado.
  7. El sistema muestra el estado de la operación.

  Alternativos: A1 el agente no está disponible (se informa, sin abortar el
  análisis); A2 error en validate/plan (el agente reporta el error y la
  operación no se aprueba); A3 el usuario rechaza la operación (queda
  registrada como rechazada).

  \subsubsection{RF16 -- Aprovisionamiento de instancias desde
  recomendaciones}

  Descripción: "El sistema deberá permitir, con la autorización explícita
  del usuario, aprovisionar la instancia recomendada mediante el agente de
  Infraestructura como Código, presentando el plan y el costo estimado para
  su aprobación antes de la ejecución, y registrando la operación en la
  cola de acciones con su resultado."
  Prioridad: Baja. CU relacionados: CU10.
